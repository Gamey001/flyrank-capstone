Before

The black-box run

Every watcher inside the process reports success.

$ curl -s localhost:8000/runs/4161ab9f-… | jq .inside_watcher.langsmith
{
  "found":   true,
  "status":  "success",
  "error":   null,
  "closed":  true
}

$ curl -s localhost:8000/runs/4161ab9f-… | jq .report
null

$ docker compose logs --no-color | grep -cEi 'error|traceback|exception'
0

$ docker compose logs --no-color | grep -cEi '137|killed|out-of-memory'
0

$ docker compose ps --format '{{.Service}} {{.Status}}'
api    Up 7 minutes
redis  Up 9 minutes (healthy)

Every service up, not one error line, and the customer's report is empty. The process that died was never in these logs. Finding out why means combing logs by hand across services, guessing which of thousands of runs was the bad one. ~14 hrs.

After

Paste one ID

The watcher that outlived the process speaks up.

$ python3 scripts/trace.py 4161ab9f-17f7-4ced-a552-2ba12de4e6cc

One ID, both views, the exact script and the exact prompt that killed it. Under 2 min.
